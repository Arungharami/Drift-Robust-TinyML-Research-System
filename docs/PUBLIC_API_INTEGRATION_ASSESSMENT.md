# Public API Integration Assessment

This is a discovery catalog, not an enabled integration. The portal currently makes no external API calls, stores no third-party API credentials, and sends no review content or research data to a public API. The decision is to defer all integrations until a concrete user need, terms review, data-protection assessment, and caching/failure design are approved.

| Provider / potential purpose | Data that would leave the portal | Privacy / terms question | Retention and caching | Limits / cost | Availability / failure design | Primary documentation |
| --- | --- | --- | --- | --- | --- | --- |
| GitHub REST API — show repository/PR metadata | Repository identifier and requested public metadata; a token only if private access is later required | Avoid sending reviewer names, private discussion, or unpublished artifacts; token scope must be least privilege | Cache metadata server-side with ETags; do not persist tokens in browser storage | Unauthenticated public access is normally 60 requests/hour per IP; authenticated requests have different limits | Treat GitHub as advisory metadata; show last cached value and a stale/unavailable notice, never block evidence display | [Rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api?apiVersion=2022-11-28), [best practices](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-the-rest-api?apiVersion=2026-03-10) |
| Zenodo REST API — discover public related datasets/records | Search terms and, if a link is followed, record identifiers | Confirm record license and attribution; do not upload project or reviewer files automatically | Cache selected record metadata with source URL and retrieval date | Rate limits and availability can change; verify before implementation | Search failures must not affect local evidence or claims; links remain optional | [Zenodo REST API](https://developers.zenodo.org/) |
| Open-Meteo — optional environmental context prototype | Approximate location/time query only; no participant, reviewer, or sensor sample identifiers | Check whether a location could reveal a collection site; aggregate or omit sensitive sites | Store only a cited, time-bounded derived snapshot if approved | Free/public service conditions may change; do not assume production SLA | Use explicit `NOT_AVAILABLE` display for optional context; do not impute environmental values | [Open-Meteo API documentation](https://open-meteo.com/en/docs) |
| OpenAlex — literature discovery support | Search terms, DOI, title, author or institution queries | Search terms can reveal unpublished research direction; do not transmit draft-review text | Cache bibliographic metadata with source and retrieval time; retain only as long as needed for bibliography work | Public API policies and limits must be checked at adoption | Keep manual bibliography workflow functional if unavailable | [OpenAlex API](https://docs.openalex.org/) |

## Adoption rule

Any later provider needs a small design record that names the exact endpoint, data classification, authentication method, terms/license review date, caching TTL, rate-limit behavior, timeout/retry policy, user-facing outage state, deletion/retention policy, and owner. API output is contextual information, not research evidence, unless independently preserved and registered by the research evidence pipeline.
